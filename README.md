# 总控台

单机、单用户的 Windows 本地开发运维面板：自动扫描本机的服务进程、监听端口、项目目录与已安装的 Agent 工具，聚合为统一面板，并以用户保存的命令启停任务。仅绑定回环地址，不对网络提供任何服务。

功能复刻自 [laogou717/local-ops](https://github.com/laogou717/local-ops)（macOS 版「总控台」），按 Windows 适配：Python 标准库 + psutil 的模块化后端，无构建、无 CDN 的原生前端。

---

## 快速开始

要求：Windows 10/11、Python 3.10+、`pip install psutil`。

```
start.bat                                 # 双击启动，自动打开 http://127.0.0.1:9600
python server.py                          # 同上（命令行）
python server.py --no-browser             # 启动但不自动开浏览器
python server.py --port 9603              # 指定首选端口（被占则依次尝试 9601–9609）
python server.py --data-dir <PATH>        # 自定义数据目录
```

- **单实例**：重复启动会检测到已运行的实例并直接打开其页面，不会起第二份服务。
- **数据目录**默认 `%APPDATA%\总控台`：
  - `config.json` —— 你的全部配置（命令单元、设置、端口基线）。每次写入前自动留一份 `config.json.bak`，改坏了可手动回滚；
  - `logs\<单元ID>.log` —— 各命令单元的输出日志（每个按 2 MB 上限自动裁剪）。
- **停止**：在运行服务的命令行窗口按 `Ctrl+C`，或点界面顶栏「停止」。停止面板**不会**结束你已启动的命令单元。

## 启动台（日常主界面）

保存常用命令为一键启停的「卡片」。命令单元分两类：

- **服务**：长期运行（如 dev server、数据库、AI Agent）；
- **任务**：跑一次就结束（如构建、安装依赖、批处理）。任务退出码约定：`0` 成功、`130` 被手动停止、其他非零为失败（异常态会聚到「异常/已结束」筛选）。

### 添加命令单元

点「+ 添加服务 / + 添加任务」（或任务区的虚线添加卡），对话框字段：

| 字段 | 说明 |
|---|---|
| 从项目选择 | 下拉选一个已扫描到的项目，自动填工作目录，并列出候选启动命令（如 `npm run dev`）供一键填入 |
| 名称 | 卡片标题，必填 |
| 服务 / 任务 | 单选，决定生命周期语义（见上） |
| 命令 | **PowerShell 命令**（优先 pwsh 7，未安装用 5.1），必填。如 `npm run dev`、`python manage.py runserver` |
| 工作目录 | 命令的执行目录，可留空（用面板进程目录） |
| 环境变量 | 每行一条 `KEY=VALUE`，`#` 开头为注释，详见[环境变量](#环境变量env--env-文件) |
| 环境变量文件 | `.env` 路径（相对工作目录或绝对路径），详见[环境变量](#环境变量env--env-文件) |

保存后卡片立即出现，并计入顶部统计。

### 卡片上的操作

| 按钮 | 说明 |
|---|---|
| 启动 / 停止（大按钮） | 启动后台运行；停止会结束**整棵进程树**（如 `npm run dev` 拉起的 node），并弹确认框 |
| ↻ 重启 | 先停止再启动（仅运行中出现） |
| ⧉ | 复制命令到剪贴板 |
| ▤ 日志 | 打开右侧日志抽屉，3 秒自动刷新 |
| ⚑ 诊断 | 规则诊断：健康问题 + 退出码 + 日志模式 → 修复建议 |
| ❯ 终端 | 在本机打开 Windows Terminal（无则 cmd），落在单元的工作目录 |
| ⌨ 编辑器 | 用 VS Code（无则资源管理器）打开单元的工作目录 |
| ✎ 编辑 | 修改名称 / 命令 / 目录 / 环境变量（运行中需先停止） |
| × 删除 | 删除单元配置（不影响已在运行的进程） |

卡片状态行：运行中显示状态、端口芯片（`:8000 ↗`，点击直接在浏览器打开该端口）、ENV 徽章、PID 与运行时长。健康检查发现阻断性问题时显示「⚠ 需检查」，点击直接进诊断。

### 排序与筛选

- **拖拽**卡片（抓住 ⋮⋮ 或卡片本体）到目标位置；或聚焦卡片后按 `Ctrl+←` / `Ctrl+→`。服务与任务两个分区独立排序。
- 分区标题右侧的筛选签（全部 / 运行中 / 已停止 / 异常）只影响显示。
- 侧栏「快捷操作 → 批量停止服务」一次确认后停止全部运行中的服务。

### 命令面板（`Ctrl+K`）

输入即搜：单元名、启停/重启/日志/诊断、在终端或编辑器打开、页面跳转、批量停止、刷新状态、切换主题。`↑` `↓` 选择，`Enter` 执行，`Esc` 关闭。

### 侧栏

- **负载曲线**：最近 120 帧整机 CPU（蓝）与内存（粉），随刷新间隔每帧推进；
- **实时动态**：单元启停、端口就绪、认领、复制等事件流，可清空；
- **小贴士**：安全机制提示。

## 服务监控（本机实况）

每 2 秒（可调）刷新一帧整机快照。

### 端口三档归属

| 归属 | 判定 | 展示 |
|---|---|---|
| **已管理** | 属主是启动台运行单元（含其子进程树） | 表内可直接看日志 |
| **项目** | 属主进程的工作目录落在某扫描根项目内 | 可「加入启动台」认领、可「忽略」 |
| **其他** | 其余全部 | 默认折叠，点「展开」查看 |

TCP 端口行带 `↗ 打开`（默认浏览器访问 `http://127.0.0.1:端口`）与 `⧉ 复制`（0.0.0.0 自动转为 127.0.0.1；IPv6 自动加方括号；UDP 端口不可点）。项目端口行还会显示该项目的 Git 分支徽章（若已配置扫描根）。

**启动者溯源**：端口属主进程带彩色徽章，标明它是谁拉起的——🤖 AI 助手（Claude Code / Codex 等）、⌨ 编辑器（VS Code / Cursor）、▸ 终端、🚀 总控台自身。仅展示，不影响任何操作。

### 关注进程

在盘点页设置里添加关键字（如 `node`、`vite`、某服务名），监控页顶部会出现 **WATCHED · 关注进程** 独立分组：凡是**进程名或命令行包含关键字**（不区分大小写）的进程都会列出，进程表中同步高亮。想不再关注，到设置里删掉关键字即可。

### 新端口发现

面板持久化一份「见过的端口」基线。新出现且非本控制台管理的监听端口会在监控页顶部弹提醒条，可一键「加入启动台」（进入认领流程）或「忽略并隐藏」（进设置可恢复）。

### 进程表

按 CPU 降序列出前 300 个进程，支持按名称 / PID / 命令行过滤。行尾「隐藏」可把同名进程全部从监控中排除（有确认框，盘点页设置里可恢复）。运行单元的进程、监听端口的进程都会打标签。

### 侧栏

实时告警（快照异常、扫描错误）、负载曲线、资源占用 TOP5（CPU / 内存切换）。

## 盘点（资产与设置）

### Agent 工具

按声明式注册表（`registry/agent-tools.json`，改 JSON 即可扩展）盘点本机 CLI 型 AI 编程工具：名称、版本、安装路径、配置目录、登录态。**登录态只判断凭据文件是否存在**，不读取、不上传内容。

### 项目

扫描根内深度 ≤3 的项目目录（package.json / pyproject.toml / manage.py / go.mod / Cargo.toml / docker-compose / index.html / .git 任一特征），列出：

- 路径与类型；
- **Git 徽章** `⎇ 分支`：绿色 = 工作区干净，橙色带 `*` = 有未提交改动（只读查询，未装 git 或非仓库则不显示）；
- 候选命令芯片：点击直接带入新建对话框；
- 「加入启动台」：预填项目信息新建单元。

识别与 Git 查询全程只读，绝不安装依赖、不执行项目代码。

### 设置面板（盘点页右侧）

| 设置 | 说明 |
|---|---|
| 扫描根 | 自动扫描的项目目录，可多个（默认是用户主目录，建议改成如 `E:\项目`） |
| 刷新间隔 | 快照轮询秒数，1–300，默认 2 |
| 任务完成通知 | 任务结束 / 服务意外退出时弹浏览器通知（首次启动单元时浏览器会请求授权；可关） |
| 已忽略端口 | 不再出现在监控页的端口，点 `×` 恢复 |
| 进程关注关键字 | 即时生效，监控页出现 WATCHED 分组 |
| 已隐藏进程 | 点 `×` 恢复显示 |

「保存设置」会持久化以上全部内容。

## 日志中心（`Ctrl+J`）

左侧列出全部单元（绿点 = 运行中），点选切换，右侧 3 秒自动刷新日志。滚到底部时自动跟随新输出；向上翻阅时不会被强制拉回。选中状态跨开关保留。

## 环境变量（env 与 .env 文件）

命令单元支持两层环境变量，启动时按以下优先级合并注入进程：

```
面板进程环境  <  .env 文件  <  手写 env（同名键覆盖前者）
```

- **手写 env**：对话框多行文本，每行 `KEY=VALUE`，`#` 注释；
- **env_file**：相对工作目录或绝对路径。支持 `#` 注释行、可选 `export ` 前缀、成对引号值（`KEY="two words"`）；文件缺失不阻断启动，但健康检查会出橙色提醒；
- 卡片上的 `ENV×2+.env` 徽章提示配置了几个变量与是否挂了文件，悬停可看明细。

示例：项目 `.env` 写 `DATABASE_URL=...`，对话框手写 `NODE_ENV=development` 覆盖默认——两者同时生效。

## 诊断与一键修复

卡片「⚑ 诊断」或「⚠ 需检查」徽章打开诊断弹窗，按规则给出可执行的建议：

- 健康类：工作目录 / 脚本 / 运行时缺失、node_modules 缺失、.env 缺失（提醒级）；
- 日志类：`Cannot find module`、命令未识别（中英文模式）、npm 脚本名写错（并列出可用脚本）、端口占用 EADDRINUSE、权限不足、Python ModuleNotFoundError、exit 9009 等；
- 依赖缺失且项目有 package.json 时出现 **「一键安装依赖」**：自动创建一次性任务（自动探测 yarn/pnpm/npm 并生成安装命令），启动并跳转日志中心实时观察。

## 总控台自身控制

顶栏「重启 / 停止」只影响面板服务，**不影响已运行的命令单元**：

- **重启**：以新进程接管同一端口，页面几秒后自动恢复；
- **停止**：面板退出（页面显示断连横幅）；单元进程继续运行。之后重新 `python server.py` 即可接管——已运行单元会被重新识别为运行中，停止它们仍需通过面板（运行令牌三重校验：令牌 + 进程创建时间 + 当前用户，不会误杀同名同端口的外部进程）。

## 安全边界

- 只添加你已检查且信任的命令和工作目录；总控台能以当前用户权限执行保存的 shell 命令。
- 仅绑定 `127.0.0.1`；写接口要求 Host 校验（防 DNS rebinding）+ 同源 Origin + 操作令牌三重防护。
- 「打开 URL」接口仅接受 http/https 地址；「打开终端 / 编辑器」只对已保存单元的工作目录执行白名单程序。
- 不通过反向代理、SSH 隧道或端口映射对外暴露；不要在共享或不受信任的用户账户中运行。
- 配置、日志可能含本机路径等敏感信息，上传前请脱敏。

## 典型工作流

**首次使用**：启动面板 → 盘点页把扫描根改成你的项目目录（如 `E:\项目`）→ 保存 → 稍候项目表出现你的项目（带 Git 徽章）→ 在项目行点候选命令或「加入启动台」→ 回启动台点「启动」→ 状态变绿、出现端口芯片 → 点端口芯片直接在浏览器打开服务。

**接到一个外部跑着的服务**：监控页项目端口行点「加入启动台」→ 对话框自动预填项目信息 → 保存并认领 → 之后可从卡片统一停止 / 看日志。

**服务起不来**：卡片「⚑ 诊断」→ 按建议修复；依赖缺失直接「一键安装依赖」。

## 常见问题

**停止会误杀别人的同名进程吗？**
不会。停止前做三重校验：命令行含本次运行令牌 + 进程创建时间与记录一致（防 PID 复用）+ 属当前用户。认领的外部进程退化为创建时间 + 用户双重校验。校验不过会明确报错而不是静默不动。

**为什么有的进程 PID 显示「（不可见）」？**
Windows 下部分系统进程不允许读取信息，端口行只显示地址。

**.env 文件写在哪？**
随你习惯，通常放项目根目录并在单元里填相对路径 `.env`。它只是注入环境，面板不会改写它。

**任务「异常」了怎么看原因？**
筛选到「异常/已结束」→ 点 ▤ 日志看最后的报错行，或 ⚑ 诊断自动匹配错误模式。

**配置改坏了怎么办？**
`%APPDATA%\总控台\config.json.bak` 是上一版备份，改回文件名即可。配置完全损坏时程序以默认配置启动，不会崩溃。

**升级会影响旧配置吗？**
schemaVersion 保持兼容：旧 `config.json` 加载时自动合并补齐新字段，旧单元原样保留。

## 开发

```
python -m pytest tests/ -q    # 全量测试（109 项，含前端契约测试）
python tools/smoke.py         # 前后端联通性冒烟（38 项，真实服务器）
```

结构：`core/server.py`（HTTP 骨架：鉴权 / 分发 / 静态文件）、`core/api/`（按域注册的 API 路由：snapshot / units / settings / inventory / console）、`core/launchpad.py`（命令单元与进程管理）、`core/scanner.py`（进程/端口快照，Windows 原生批量枚举 + psutil 回退）、`core/attribution.py`（进程溯源）、`core/diagnose.py`（健康检查与诊断）、`core/inventory.py`（Agent 工具与项目盘点，含只读 Git 信息）、`core/integrations.py`（终端 / 编辑器集成）、`core/security.py`（Host/Origin 校验）、`core/store.py`（配置持久化与 schema 迁移）、`static/js/`（原生 ES Modules 前端）、`registry/agent-tools.json`（Agent 工具注册表）、`tools/smoke.py`（联通性冒烟）。

版本号以根目录 `VERSION` 为单一权威来源；变更记录见 [CHANGELOG.md](CHANGELOG.md)，术语表见 [CONTEXT.md](CONTEXT.md)。
