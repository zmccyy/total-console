# 总控台 v0.3.0 全面升级方案（Loop Engineering 推进）

## 现状诊断（探索结论）

- **后端**：`core/server.py` 723 行 god-module（路由 if-chain + 编排 + 缓存 + SSE 混杂）；单元编辑绕过 Launchpad 直改配置，存在 3 条保存路径；config 共享 dict 无显式锁；静默失败点：taskkill 返回值未校验、inventory 后台线程无 except（registry 读取失败会反复崩线程 → /api/inventory 500）。
- **前端**：`static/app.js` 1211 行全局作用域单文件，每次 SSE tick 对全部卡片/表格 innerHTML 全量重渲染；确认 1 个真 bug：命令面板搜索有损（app.js:1002 过滤后覆盖池子）；多个 GET 绕过 `api()` 不带 token；主题加载闪烁；两套重复日志查看器。
- **功能差距**（对标原版 local-ops + PM2/Dockge 类工具）：点端口打开浏览器、进程关键字关注列表、端口/进程隐藏与恢复、负载曲线、终端/编辑器一键打开、环境变量管理、Git 项目信息、依赖一键修复。
- **测试基建良好**：85 项测试含真实 HTTP/进程集成测试，是重构的安全网。

## 固定纪律（每个 Loop 相同）

1. 实现 → `python -m pytest tests/ -q` 全绿 → `python tools/smoke.py` 全 API 联通全绿 → 涉及 UI 的 Loop 另用 browser-use:web-gui-tester 驱动浏览器实测 → 发现报错立即修复后重验。
2. 验证通过才 `git commit`（每闭环一提交，提交信息含 Loop 编号与验证结果）。
3. 不新增运行时依赖（遵守 ADR-0001：psutil 唯一依赖）；不引入构建步骤；仅绑 127.0.0.1 的安全边界不动。

## Loop 0 — 验证基建（先跑通基准闭环）

- 新增 `tools/smoke.py`：临时数据目录 + 端口 0 启动真实服务器，逐一请求全部 API 路由（GET/POST/PUT/DELETE 含 4xx 分支）、SSE 首帧、静态页与 app.js 可达，输出逐项 pass/fail，任何失败非零退出。此脚本即后续每步的「前后端联通性」验证器。
- 跑通基线：pytest 85 项 + smoke 全绿，提交 Loop 0。

## Loop 1 — 后端架构骨架（行为保持重构）

- 路由注册表 `core/routes.py`（method + 路径模式 + 鉴权级别：公开 GET / 需 token 写接口），`core/server.py` 拆出 `core/api/` 分域模块：`units.py`、`snapshot.py`、`settings.py`、`inventory.py`、`console_logs.py`。
- 领域规则归位：编辑/删除的运行态校验收进 `Launchpad`；统一为单一保存路径；config 读写加显式锁。
- 修静默失败：taskkill 结果校验（失败则单元不标记 stopped 并报错）、inventory 线程 try/except+日志、tick 循环异常记录；清理诊断死代码、统一 poll_interval 默认值（2s）。
- 验证：85 测试 + smoke 全绿（行为未变）→ 提交。

## Loop 2 — 前端骨架（ES Modules 拆分，仍零构建）

- `static/app.js` → `static/js/`：`main.js`（boot/SSE/定时器）、`api.js`（统一助手，所有请求含 GET 一致带 token）、`state.js`、`util.js`、`render/`（launchpad / monitor / inventory / palette / logs）、`handlers.js`；`index.html` 改 `<script type="module">`。
- 全量 innerHTML 渲染改定向更新（卡片与表格按 key 增量更新）；修命令面板搜索有损 bug；内联默认主题消除闪烁；两个日志查看器合一；移除死代码；`style.css` 浅色主题 9 处覆盖收敛为变量切换。
- 新增 `tests/test_frontend_contract.py`（零浏览器契约测试）：index.html 引用的 js 文件存在 + 前端调用的 /api/* 字符串集合 ⊆ 后端路由注册表。
- 验证：pytest + smoke + 浏览器实测（三视图切换、启停单元、命令面板、日志中心）→ 提交。

## Loop 3 — 开发体验包（3a/3b/3c 三个子闭环分别提交）

- **3a 端口快速操作**：监听端口行与单元卡片加「打开浏览器」「复制 URL」（http://127.0.0.1:port）；服务/项目端口均可用。
- **3b 终端/编辑器集成**：`POST /api/units/<id>/open-terminal`（探测 wt.exe，回退 `cmd /c start`）与 `/open-editor`（探测 VS Code `code`，回退资源管理器）；仅对受管单元的工作目录执行，程序白名单探测；卡片按钮 + 命令面板入口。
- **3c 环境变量**：单元 schema 增 `env`（键值对）与 `env_file`（.env 解析 KEY=VALUE），启动时注入 Popen 环境；编辑对话框加环境变量区；健康检查提示 .env 缺失。schemaVersion 保持 2（默认合并即兼容旧配置）。
- 每项：后端测试 + 前端 UI + smoke 路由扩充 + 浏览器实测 → 提交。

## Loop 4 — 监控补齐包（补齐原版 local-ops 能力）

- **进程关键字关注列表**：设置中保存关键字，匹配进程在监控视图独立分组展示并高亮。
- **隐藏与恢复**：端口「忽略并隐藏」升级为可管理（ignored_ports 在设置中列出可恢复）；外部进程支持隐藏/恢复（hidden_pids 持久化）。
- **负载曲线**：后端内存 ring buffer 保留最近 ~120 帧的整机 CPU/内存，snapshot 事件携带；前端零依赖 SVG sparkline（启动台侧栏 + 监控视图）。
- 验证同上 → 提交。

## Loop 5 — 项目洞察包

- **Git 信息**：盘点扫描对识别项目执行只读 `git branch --show-current` + `git status --porcelain`（带超时、TTL 缓存、git 缺失静默跳过）；项目表与端口归属显示分支徽章。
- **依赖一键修复**：诊断的「缺依赖」提示升级为可执行按钮——一键创建一次性任务单元执行 `npm/pnpm/yarn install` 并跳转日志中心观察。
- 验证同上 → 提交。

## Loop 6 — 收尾

- `CHANGELOG.md` + `VERSION`（对齐原版做法）；README 功能清单、CONTEXT.md 术语表补充新概念（关注列表、环境变量、负载曲线）。
- 旧配置兼容性验证（含 .bak、schema 迁移路径）。
- 端到端验收：pytest 全量 + smoke + 浏览器完整链路（添加带环境变量的单元 → 启动 → 看日志 → 打开终端 → 停止 → 查看负载曲线）。
- 用 requesting-code-review skill 审查整体 diff，修复发现的问题 → v0.3.0 提交。

## 风险与对策

- 路由重构回归风险 → 85 项现有测试为安全网，Loop 1 严格行为保持，不改任何响应字段。
- ES Modules 老浏览器兼容 → 本机开发者场景，现代 Chrome/Edge 均支持。
- Windows 进程操作风险 → 沿用运行令牌三重校验不放松；taskkill 结果校验为增强而非放松。
